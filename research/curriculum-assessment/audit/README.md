# Этап 02 · Методологический аудит курса A1–A2

Снимок локального каталога от 26 ноября 2026 года. Единица аудита — учебная задача с доступными ученику условиями и ответом, который принимает текущая проверка. Названия и метки уровня показывают авторское назначение урока. Вывод об учебной возможности опирается на содержание задания. Профиль реальных учащихся требует отдельных данных об их выполнении. [Методологическая база](../METHODOLOGY_BASELINE.md) · [CEFR](../CEFR_FRAMEWORK.md)

| Файл | Что в нём искать |
| --- | --- |
| [AUDIT_REPORT.md](AUDIT_REPORT.md) | Выводы по уровням, переходу A1–A2, приоритетам и ориентировочному объёму расширения. |
| [COURSE_INVENTORY.csv](COURSE_INVENTORY.csv) | Порядок курса, существующие ID уроков, шагов и вопросов, ключевые форматы и условия разблокировки. |
| [LESSON_AUDIT.csv](LESSON_AUDIT.csv) | Одна оценка на урок. Цели, объяснение, практика, самостоятельность, уровень, достаточность, примеры и рекомендация. |
| [COVERAGE_MATRIX.csv](COVERAGE_MATRIX.csv) | Цели Pre-A1, A1 и A2, свидетельства, недостающие виды практики и ограничения. Pre-A1 здесь описывает входные предпосылки. |
| [PREREQUISITES.csv](PREREQUISITES.csv) | Образовательные зависимости между уроками и целями, включая переход A1–A2. |
| [GAP_REGISTER.csv](GAP_REGISTER.csv) | Системные и значимые локальные пробелы, приоритет, уверенность и предварительная мера. |

## Как читать таблицы

Файлы CSV в UTF-8, с разделителем-запятой. Значения внутри списков разделены вертикальной чертой. `position` — порядковый номер, `lesson_id` — стабильный идентификатор. `source_path` указан относительно корня репозитория. В `evidence_ids` идентификатор шага относится к указанному уроку. Для вопроса используется полный `question.id`, а в JSON расширения его младшая часть хранится в первом элементе записи. `coverage` показывает статус каждой связанной цели в данном уроке. `objective_id` вида `A1-…` — ключ задачи курса для этого аудита. `gap_id` связывает выводы с реестром.

| Статус | Операциональный смысл |
| --- | --- |
| `NOT_COVERED` | У цели отсутствует целевое объяснение или задание. Случайное появление слова или фразы не даёт покрытия. |
| `INTRODUCED` | Умение показано на примере или объяснено, соответствующее действие ученика ещё не требуется. |
| `PRACTICED` | Ученик выполняет действие в направляемом упражнении, например воспроизводит готовую формулу или переносит отдельное поле. |
| `ASSESSED` | Есть возможность самостоятельной проверки узкого действия на новом материале с наблюдаемым критерием. Для вывода об отдельной попытке важны первая сдача без подсказки и реальные условия. |
| `INSUFFICIENT_EVIDENCE` | Доступные материалы допускают несколько интерпретаций либо их недостаточно для связи с конкретной шкалой. |
| `NOT_SUPPORTED` | Для цели сейчас отсутствует необходимая модальность или процедура оценивания, например звучащий вход, обмен устными репликами или проверка свободного текста по рубрике. |

В матрице указывается сильнейшее подтверждённое состояние для сформулированной цели. Количество строк с `ASSESSED` описывает проверяемые действия, а вывод об уровне CEFR зависит от диапазона задач и качества свидетельств по каждой модальности. `KEEP` означает, что урок пригоден в рамках своей узкой цели. `SUPPLEMENT`, `SPLIT` и `REORDER` обозначают основное приоритетное действие по уроку. Приоритеты `P0–P3` применяются к проблемам, уверенность `HIGH / MEDIUM / LOW` — к заключению и качеству его подтверждения.

В `PREREQUISITES.csv` указаны `REQUIRED` (без умения целевое действие существенно затруднено), `RECOMMENDED` (умение снижает нагрузку), `PREVIEW` (допустимое предварительное знакомство), `SPIRAL` (знакомый материал используется глубже) и `INDEPENDENT` (достаточна локальная подготовка). Для `LATE` и `MISSING` таблица фиксирует наблюдение об отсутствующей или поздней опоре. Только доступные `REQUIRED` образуют проверяемый граф действующих методических предпосылок. Фактический механизм доступа для новой истории прохождения требует завершения всех предыдущих уроков. Старые мигрированные достижения имеют особый режим сохранения доступа. ## Метод работы и границы

1. Каталог и насыщенный учебный контент загружены в памяти через действующий реестр. Выгрузка включала все блоки уроков, фактические инструкции, ожидаемые ответы и действующие поправки к условиям. Временные рабочие файлы использовались вне репозитория.
2. Аудиторы разобрали уроки по своим уровням. Внутри урока однотипные задания сгруппированы по способу ответа, опоре, проверяемому смыслу и требованиям к ключу. В итоговой строке приведены показательные ID, полные списки ID сохраняются в инвентаризации. Переход между уровнями и существенные выводы сверены выборочно по исходным данным.
3. Привязка к CEFR использует конкретную шкалу из [исследования первого этапа](../CEFR_FRAMEWORK.md). Точная ступень English Profile указывается лишь там, где её можно подтвердить. Порядок серии служит сравнительным ориентиром. [Учебные программы](../TEXTBOOK_RESEARCH.md)
4. Целостность проверяется по идентификаторам, количеству и связям. Вариант выбора сверяется с заданным вариантом, ввод — с перечнем принятых ответов после нормализации пробелов, апострофов и, по настройке, регистра и конечной пунктуации. Статическая валидация охватывает заданные ключи и варианты выбора. Для полного набора естественных ответов и учебного эффекта нужны другие свидетельства. [Проверка ключей](../../../src/lib/grading.ts)

Для следующего этапа сначала отфильтруйте `GAP_REGISTER.csv` по приоритету, затем сопоставьте `objective_id` с конкретными уроками и зависимостями. Объём новой программы уточняйте по тому, какие задачи можно добавить в существующий урок и какие требуют отдельного места для переноса или самопроверки.

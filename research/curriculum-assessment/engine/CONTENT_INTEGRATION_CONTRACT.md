# Lessons & QA integration

The [approved blueprint](../blueprint/CURRICULUM_BLUEPRINT.md) supplies planning IDs and objective links. Run `python3 scripts/generate-adaptive-catalog.py --check` to check the derived model. Regenerate the JSON with the same command without `--check` after an authorised change to the source tables. The generated catalogue is metadata. The actual installed lesson registry determines `readyLessons`.

1. Register the completed lesson in the regular course with its stable catalogue ID and existing lesson schema. Keep planned rows out of the installed registry until content and routes work.
2. Use an approved placement criterion from `pilotCriteria` or add an explicit `Criterion {id, version, group, objectives}` for in-lesson actions. Objectives must belong to that knowledge group. Supply explicit skip and readiness criterion profiles only for their approved purpose.
3. Register a `PracticeItem` for each designated observation. It uses `lessonId`, `stepId`, `itemId`, `itemRevision`, `keyId`, `keyRevision`, `criterion`, `family`, `stimulus`, `role`, `designated`, `keyVisible` and `wrongAttribution`. Validate these against the exact ready question and its key. Use one designated result per criterion for a linked product. Mark ambiguous attribution when an incorrect response could have several causes.
4. Author a `DiagnosticItem` with the same evidence metadata and a regular `Question` as its key, prompt and explanation. R uses one choice with a single correct option. P requires an actual blank or written response without visible keys. Author finite natural variants and explicit normalization for fields where register, time or punctuation matters. Diagnostic outcomes are committed without storing the raw answer string in the sidecar.
5. Define two or more `Form` records with ordered slots for D0, D0R, D1, D2-BASE, D2-UP and D3. A slot identifies its block, pilot group, role and ordered pool of item IDs. Avoid shared families or stimuli across separate slots and forms for the same criterion. Include enough fresh families to support the full branch set and a retake.
6. Register a `CheckpointProfile` by its approved ID and designated item IDs, with explicit versioned criteria for every readiness group in that row. CP-A1 and CP-061 require a present positive from the current attempt for each active readiness criterion as well as CONFIRMED in history. CP-061 needs an approved lesson criterion for K-A2-PLAN. CP-PRE directs the learner toward A1 or specific preparation. The A2 final stays within the existing text course.

Call `validateCatalogue()` for graph and reference checks, and `validateAdaptiveContent(rules, bank, practice, true)` for release metadata. Update item/key revisions when meaning or accepted variants change. Register withdrawn keys so previously eligible signs are excluded. The automated checks can validate declared roles, links, formats, keys and families. Independent editorial review is required to establish actual material independence, absence of answer leaks, content quality and criterion validity. See [bank specification](../assessment/DIAGNOSTIC_BANK_SPEC.md) and [pilot validation](../assessment/PILOT_VALIDATION_PLAN.md).

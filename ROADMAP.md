# Roadmap

| Stage | Input and handoff needed to proceed |
| --- | --- |
| 1. Establish educational standards | Record source provenance, scope and limits for the audit. |
| 2. Audit existing lessons | Map coverage and gaps against the standards and hand the inventory to curriculum planning. |
| 3. Design the target program | Map the 140 sessions and their prerequisites to learning objectives and authoring packages. |
| 4. Specify assessment and adaptation | Define placement, evidence, checkpoints, acceptance scenarios and pilot criteria for the engine and UI. |
| 5. Implement the engine | Direction 03 confirms the handoff, publishes reviewed commits to a task branch and demonstrates progress compatibility and the agreed acceptance cases. |
| 6. Integrate the interface | Directions 02 and 03 follow the engine contract and verify navigation, recommendation states, mobile and desktop layouts and both themes. |
| 7. Author and extend lessons | Direction 04 follows the curriculum, checks prerequisites, preserves IDs and tests lessons against the authoring contract. |
| 8. Integrate and release | Verify the integrated branch, including existing progress. With owner approval, promote a tested revision to main, monitor Pages and verify the live site. |

[Status](PROJECT_STATUS.md) records completion. The [research index](research/curriculum-assessment/README.md) links to the first four stages. UI and lesson work can be planned from the written specifications. Integration depends on a confirmed engine contract.

Long-term ideas for separate decisions include listening, narrated audio, voice recording, pronunciation practice, video, server infrastructure and monetization. These are possible directions without delivery commitments.
